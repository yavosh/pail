# KMS-compatible API

## Scope

Serve KMS on pail's existing listener with the existing credentials, account, and region.
Implement symmetric encryption and key management for local application tests.

- Support AWS JSON 1.1, `TrentService` targets, and SigV4 scope `kms`.
- Persist customer managed `SYMMETRIC_DEFAULT`, `ENCRYPT_DECRYPT`, `AWS_KMS` keys.
- Implement create, describe, list, description updates, enable, disable, scheduled deletion, and cancellation.
- Implement alias creation, updates, deletion, listing, and key identifier resolution.
- Implement resource tags and key policy storage without IAM policy enforcement.
- Implement encrypt, decrypt, reencrypt, data key generation, and random byte generation.
- Authenticate encryption context and ciphertext metadata with AES-256-GCM.
- Keep cryptographic operations and key state changes under the engine mutex.
- Commit state atomically before exposing changes in memory. Store key material in files with mode `0600`.
- Expire scheduled deletions lazily. Start no background goroutine.
- Reject unsupported key types, external stores, grants, attestation, and rotation explicitly.

S3, SQS, and SNS encryption integration remains a separate effort.
Ciphertext is specific to pail and cannot be exchanged with AWS KMS.
Key material is stored locally without HSM protection or encryption at rest.

## Validation

- Exercise the real server with the AWS Go SDK and signed raw requests.
- Verify encryption context, tampering, wrong keys, aliases, state transitions, and pagination.
- Verify persistence, canceled operations, storage failures, and concurrent state changes.
- Add differential scenarios and approved AWS recordings. Never edit golden files manually.
- Run formatting, lint, race tests, vulnerability checks, and a pure-Go build.

AWS recording requires approval before creating shared resources.

## Verification evidence

- AWS Go SDK, AWS CLI, and pinned boto3 tests pass against pail.
- The approved AWS recording contains 25 exchanges. Replay matches all exchanges.
- Recording exposed cache headers, empty response bodies, alias counts, and key origins; the implementation now matches them.
- Both AWS test keys were verified in `PendingDeletion`, with seven-day deletion schedules. The temporary alias was deleted.
- Full race tests, lint, vulnerability checks, and a CGO-disabled build pass.
- The production binary has no AWS SDK dependencies.
