# pail SQS and SNS

Date: 2026-10-09. Status: in progress.

## Goal

pail serves a local Amazon SQS and Amazon SNS next to S3. Tests and CI/CD
harnesses can use the AWS SDKs, the AWS CLI, and boto3 against one endpoint.
Like the S3 side, the goal is API compatibility, not scale.

## Non-goals

- Production use, scale, or high availability.
- IAM, queue policies, topic policies, and permission actions.
- SMS, mobile push, platform applications, and data protection in SNS.
- SQS message move tasks.
- The legacy SQS query protocol.
- SNS FIFO topics in v1.

Unsupported actions fail loudly, so a test never passes by accident.

## Decisions

| Topic | Decision | Why |
| --- | --- | --- |
| SQS protocol | AWS JSON 1.0. Requests are `POST /` with `X-Amz-Target: AmazonSQS.<Op>`. Errors also carry `x-amzn-query-error: <Code>;Sender`. | Current SDKs speak it. The service model is `awsQueryCompatible`. |
| SNS protocol | AWS query protocol. Requests are form-encoded `Action=<Op>&Version=2010-03-31`. Responses are XML. | SNS has no JSON protocol. |
| Listener | One listener and one port serve S3, SQS, and SNS. | Clients need one endpoint. |
| Routing | The router reads the service from the SigV4 credential scope. An unsigned request with `X-Amz-Target: AmazonSQS.*` goes to SQS. Everything else goes to S3. | Routing never reads the body. S3 behavior stays unchanged. |
| Authentication | Same access key pair as S3. Header signatures only. The verifier buffers the body and hashes it. | SQS and SNS clients do not send `x-amz-content-sha256`. |
| Persistence | Queue, topic, and subscription definitions persist on disk. Messages live in memory. | Tests recreate messages. A restart keeps the setup. |
| Account ID | `000000000000`. | A fixed value keeps ARNs and queue URLs predictable. |
| v1 features | Standard and FIFO queues, dead-letter queues, SNS topics, SNS-to-SQS delivery, filter policies, and HTTP/HTTPS delivery. | These cover the common test flows. |
| Time | Engines compare `time.Now()` on each call. No background timer per message. | `testing/synctest` can drive all timing. |

## AWS validation stage

Every SQS and SNS PR has an AWS validation stage, as S3 has.

- Each new behavior adds `test/diff` scenarios.
- A maintainer records golden files against real AWS with
  `go test ./test/diff -record`.
- New steps start in `test/diff/testdata/pending.txt`.
- A PR is done when its steps pass and leave `pending.txt`.
- Fix a difference in pail, or list it in `known-diffs.txt` with a reason and
  an issue link.

PR 2 builds this stage. PRs 3 to 8 use it.

## Unverified

PR 1 wrote the error codes from memory. The PR 2 recordings verified these:

- SQS answers a missing signature with `AccessDenied` (`AccessDeniedException`).
  SNS answers it with `MissingAuthenticationToken`.
- Both services report an unknown key as `InvalidClientTokenId`, and a bad
  signature or a skewed clock as `SignatureDoesNotMatch`.
- SQS sends the legacy code `AWS.SimpleQueueService.NonExistentQueue` for a
  missing queue, and an empty body for `DeleteMessage` and `DeleteQueue`.

The PR 4 recordings (`sqs-message-attributes`, `sqs-visibility`, `sqs-batches`, and `sqs-errors`) verified these:

- `MD5OfMessageAttributes` uses the algorithm in `internal/queue`. On a filtered
  receive, it covers only the returned attributes.
- `MessageAttributeNames` `prefix.*` matches names that start with the text
  before `.*`, without the dot. A receive that returns no attributes omits the checksum.
- `ChangeMessageVisibility` with the latest handle applies even when the message
  is visible again, and hides it. A stale handle is not an error for `DeleteMessage`.
- `ReceiptHandleIsInvalid` is HTTP 404.
- `InvalidParameterValue` has `__type` `com.amazon.coral.service#InvalidParameterValueException`.
  An empty `MessageBody` is `MissingRequiredParameterException` with the code `MissingParameter`.
  A missing `QueueName` is `InvalidParameterValue`.
- An unknown operation is `UnknownOperationException` with the code `InvalidAction`.
  Malformed JSON is `SerializationException` with the code `MalformedInput`.
- A standard queue accepts `MessageGroupId` on `SendMessage` and `SendMessageBatch`.

These are still unverified:

- `IncompleteSignature` and `RequestEntityTooLarge`.
- `MissingParameter` for a missing `QueueUrl` or `ReceiptHandle`, and the code for a missing `VisibilityTimeout`.
- `MessageDeduplicationId` on a standard queue.
- The per-entry `InternalError` code, and `StringListValues` and `BinaryListValues`.
- `SerializationException` for a body that is valid JSON but not an object.
- `UnsupportedOperation` for model operations that pail does not implement.
- The PR 5 recordings (`sqs-fifo`, `sqs-dead-letter`, `sqs-fair-queue`) verified the FIFO creation and attribute errors, the attributes `All` returns for a FIFO queue, the send rules, deduplication, group locking, the content deduplication ID (SHA-256 of the body), the stored forms of `RedrivePolicy` and `RedriveAllowPolicy`, the dead-letter target errors (including an out-of-range `maxReceiveCount`, which returns `InvalidParameterValue`), the move with its kept receive count and `DeadLetterQueueSourceArn`, the empty `ListDeadLetterSourceQueues` response (`{}`), and `MessageGroupId` on a standard queue. AWS lists dead-letter sources with eventual consistency, which `known-diffs.txt` records. Still unverified:
  - The exact 5-minute deduplication boundary, the `messageGroup` scope's behavior, and the sequence number format (the normalizer masks it).
  - `RedriveAllowPolicy` `byQueue`, a queue that targets itself, a deleted target, and paging in `ListDeadLetterSourceQueues`.
  - `FifoQueue` `false` on a standard queue.
- Whether an old receipt handle stays valid after a new receive, beyond what the engine tests assume.
- Which HTTP failures AWS retries on delivery.
- The PR 6 recordings (`sns-topic-attributes`, `sns-sqs-delivery`, `sns-publish-batch`, `sns-errors`) verified these:
  - The order and values of the topic and subscription attributes, with `SubscriptionPrincipal` first, and the member order of tags, subscription lists, and batch results.
  - `CreateTopic` is idempotent, and a conflicting attribute, an invalid name, and a `.fifo` name return `InvalidParameter`. `DeleteTopic` of a deleted topic succeeds. A deleted topic returns `NotFound` for reads and `Publish`.
  - `TagResource` and `UntagResource` return an empty `Result` element.
  - The envelope, raw delivery with `String.Array`, and `MessageStructure` `json` in an SQS delivery.
  - `PublishBatch` always writes `Failed` first. An empty batch and a missing `Message` return `ValidationError`. Too many entries, duplicate IDs, and a bad ID return their own codes. A failed entry has `InvalidParameter` and `SenderFault` `true`.
  - A standard topic accepts `MessageGroupId`.
  - Bad protocol, bad endpoint, a long subject, a bad message structure, a missing subscription, and an unknown action.
- Still unverified for SNS:
  - Whether pail's forwarding of `MessageGroupId` to SQS matches AWS, and `MessageDeduplicationId` on a standard topic.
  - The optional topic attributes' positions, the `EffectiveDeliveryPolicy` of a topic with a `DeliveryPolicy`, and the shape of `SubscriptionPrincipal`.
  - `TagLimitExceeded`, `ResourceNotFound` for tag operations, `BatchRequestTooLong`, and an empty `Successful` list.
  - `ParameterValueInvalid` for attribute errors, `Unsubscribe` of a missing subscription, and a FIFO queue endpoint on a standard topic.
- The PR 7 recording (`sns-filter-policies`) verified these:
  - The `GetSubscriptionAttributes` positions of `FilterPolicy` and `FilterPolicyScope`. Both appear only while a policy is set, and `{}` removes the policy.
  - Exact, numeric range, prefix, `anything-but` list, and `exists` matching, `String.Array` any-match, and that a `String` attribute never matches `numeric`.
  - Body scope: nested paths, array any-match, and no match for a body that is not JSON.
  - `InvalidParameter` for an unknown operator, a policy that is not JSON, a nested policy in attribute scope, 6 keys, and 156 combinations.
- Still unverified for filter policies: `anything-but` on an absent attribute or a value of another type, `exists` `false` on a missing body path, a body policy with `MessageStructure` `json`, and how AWS counts nested keys.
